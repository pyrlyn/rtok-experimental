# Маршрутизация моделей (D9)

**Статус: включается явно, только для вызовов `internal` и `bulk`; маршрутизация ходов агента — запланировано / Later.**
Выключено по умолчанию, правил в поставке нет, lane `agent` не маршрутизируется никогда. **Это отдельное направление работы, не связанное с
Batch и Flex** (`docs/batch-flex.md`): они меняют то, *как* или *когда*
запрос тарифицируется на том же (или асинхронном) интерфейсе; маршрутизация моделей меняет то,
*какую* строку `model` передают дальше синхронные чат-протоколы.

Источник замысла: решение **D9** в `plan.md`, вариант
**#3** в `research.md` §16.3 (а также sticky upstream #1 / I-84), бэклог экономии токенов I-101 в `ideas.md`.
Поведение, которое не подключено в `src/proxy/`, помечено как **запланировано**.

## Что это такое

D9 (*Agents are provider-agnostic*): маршрутизация по задаче — недорогие модели для
механической работы, средний уровень для написания кода, высокопроизводительные для исследований только
после подтверждения пользователем. Названия продуктов-хостов не определяют реализацию.

`research.md` §16.3 #3 (*Model / tier routing by job*):

- Дешёвая модель для форматирования / классификации / подготовки к expand
- Средняя для редактирования
- Дорогая только после подтверждения
- Эффект в основном в **$** (сырое количество токенов меняется мало)
- Нужны **политика маршрутизатора + измерение**, чтобы заявленная «экономия» была в долларах,
  а не в ощущениях

rtok сегодня — это промежуточный слой (хуки, MCP, API-прокси), а **не**
маршрутизатор моделей по умолчанию. Модель по-прежнему выбирают агенты (или хост);
прокси оставляет `model` таким, каким его отправил клиент.

## Как это работает в rtok

Только в `rtok proxy` (`src/proxy/`), на JSON-протоколах чата, где `model` лежит в теле
(`/v1/messages`, `/v1/chat/completions`, `/v1/responses`). Хуки и MCP не видят HTTP-тела
запросов к LLM, поэтому не могут реализовать D9. Gemini указывает модель в пути, который
маршрутизация не переписывает, поэтому вызов Gemini не маршрутизируется никогда.

- **Какие вызовы.** `internal` (собственные вызовы моделей из rtok) и lane `bulk`
  (`src/proxy/lane.rs`, `Lane::route`). Ходы агента, `batch`, `files`, `embeddings` и `meta`
  не маршрутизируются никогда. Маршрутизации ходов агента сначала нужен бенч I-101, она остаётся Later.
- **Таблица политик.** `[proxy.routing]` (`enabled`, выключено) и по одному правилу на lane
  (`[proxy.routing.bulk]`, `[proxy.routing.internal]`): `from` (точные id или `prefix*`), `to`,
  `provider` и `gate`. Правило работает, только когда заданы `from`, `to` и `gate`. Перенос lane
  на шлюз другого провайдера — это `[proxy.lanes.<lane>] upstream`.
- **Контроль качества (I-101).** rtok не видит, достаточно ли хороша дешёвая модель, поэтому
  `gate` должен называть бенч оператора для этой замены; rtok его не читает и не оценивает.
  Правила по умолчанию нет, утверждений о качестве rtok не делает.
- **Переписывание.** `shape_request` заменяет `model` в теле до записи вызова, поэтому
  `calls.model_id`, `usage.model` (и провайдер, если правило его называет) — это модель,
  которая обслужила вызов. Журнал вызова хранит `model route on the <lane> lane: <from> -> <to>`,
  а строка измерения `model_route` помечает его (экономия токенов не заявляется).
- **Доллары.** `rtok stats --price` добавляет `cost by lane`: каждая lane оценена по моделям,
  которые её обслужили. Сравните её на одной нагрузке с выключенной и включённой маршрутизацией;
  эта разница — единственная экономия, о которой rtok сообщает для маршрутизации.

Никакого прозрачного преобразования sync→Batch; маршрутизация не ставит запросы в очередь Batch и
не задаёт `service_tier` для Flex. Это остаётся в `[proxy.batch]` / `[proxy.flex]`.

## Конфигурация

См. [config.md](config.md#proxyrouting). Пример:

```toml
[proxy.routing]
enabled = true

[proxy.routing.bulk]
from = ["claude-sonnet-*"]
to = "claude-haiku-4-5"
gate = "bench/bulk-haiku-2026-10.md"
```

Sticky upstream (`sticky`, I-84) сюда не входит и пока не является ключом.

## Статус

| Компонент | Статус |
|-------|--------|
| Решение D9 | записано в `plan.md` |
| Правила `[proxy.routing]` для `internal` и `bulk` | реализовано, выключено по умолчанию |
| Замена `model` до записи вызова | реализовано (протоколы с JSON-телом) |
| `cost by lane` в `rtok stats --price` | реализовано |
| Бенч качества за заменой (I-101) | **за оператором**: настоящему бенчу нужны настоящие модели и нагрузка, rtok их не поставляет |
| Gemini (модель в пути) | не маршрутизируется |
| Маршрутизация ходов агента | **Later** — заблокирована бенчем I-101 |
| Sticky upstream (I-84) | в форме решения; может появиться вместе с работой над кешем промпта независимо |
