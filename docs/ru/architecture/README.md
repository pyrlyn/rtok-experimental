# Диаграммы архитектуры

У каждой части rtok здесь есть [диаграмма D2](https://d2lang.com) и страница, которая проходит по ней,
называя код, за которым стоит каждый блок. Начните с обзора, затем проследите запрос через поверхность,
которая вас интересует, и откройте нужный плагин.

[`architecture.md`](../../../architecture.md) излагает принципы и решения в прозе; эти страницы показывают механизм.

## Редактирование диаграммы

Исходник — файл `.d2`; соседний `.svg` генерируется и хранится в репозитории. SVG рисуются в процессе
чистым Rust-бэкендом [`d2-render`](https://crates.io/crates/d2-render), поэтому бинарник `d2` не нужен.

1. Отредактируйте `<name>.d2` и его страницу `<name>.md`.
2. Выполните `just diagrams`. Команда перерисовывает каждый устаревший SVG и завершается с ошибкой, если исходник
   использует конструкцию, которую нативный бэкенд не рисует (`sql_table`, `sequence_diagram`, Markdown-подписи, `near`
   на вложенных фигурах, импорты, слои, …), чтобы закоммиченная картинка никогда не теряла часть
   исходника.
3. `cargo test -p rtok --test diagrams` (входит в `just docs-check`) падает, когда SVG отсутствует или старше
   своего исходника, и когда у диаграммы нет страницы.

Держите общую палитру в начале каждого файла: синий для поверхностей, фиолетовый для рантайма,
зелёный для частей плагинов, янтарный для данных, розовый для вывода оператора, серый для всего,
что находится вне rtok. У новой страницы также есть перевод в `docs/ru/` и `docs/uk/`.
