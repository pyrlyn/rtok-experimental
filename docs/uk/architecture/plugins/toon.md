# Плагін toon

![Проксі передає результат інструмента до toon, який пропускає блоки з живої зони, блоки з уже прийнятим рішенням і блоки, що не є таблицями; решту він архівує як масив JSON і замінює таблицею TOON з вказівником expand](../../../architecture/plugins/toon.svg)

Джерело: [`toon.d2`](../../../architecture/plugins/toon.d2). Документація плагіна: [README](../../../../src/plugins/toon/README.md). Індекс: [усі діаграми](../README.md).

`toon` перекодовує масив JSON з однорідних об'єктів, знайдений у старому результаті інструмента,
як рядок заголовка плюс один рядок з комами на кожен запис. Саме повторення кожного ключа в кожному
записі коштує токенів в оригіналі. Плагін працює лише на поверхні проксі, через
`Plugin::proxy_filter`, і переписує блок лише тоді, коли власна оцінка токенів каже, що результат
стане меншим.

## Покроково

1. **Проксі пропонує результати інструментів.** `rtok proxy` будує `WireRequest`;
   `ToonPlugin::proxy_filter` одразу повертається, коли `[plugins.toon] enabled` має значення false
   (у маніфесті `default_on: true`).
2. **Живу зону пропущено.** `rewrite` бере `min_rows` з конфігурації й пропускає результати
   через `archive::outside_live_zone`, тож останні `[plugins.archive] keep_turns` ходів
   лишаються побайтово незмінними.
3. **Збережене рішення має перевагу.** `rewrite_block` читає текст результату інструмента через
   `archive::block_text` (або JSON голого масиву) і шукає `cx.archive_decision(tool_use_id)`.
   Розгорнутий id або вказівник, записаний `archive` чи `json_tree` (`skips_foreign_pointer`),
   лишається без змін. Вказівник, що починається з `[toon `, відтворюється як є і вимірюється як
   рядок `toon`/`encode`.
4. **Лише однорідні таблиці.** `tabular_keys` приймає масив щонайменше з `min_rows` об'єктів
   (ключ конфігурації `min_rows`), які мають щонайменше три ключі, однакові набори ключів і лише
   скалярні значення, а ключі яких не потребують лапок.
5. **Кодування і перевірка розміру.** `encode` записує `[N]{k1,k2,…}:` і по одному рядку з відступом
   на кожен запис; `needs_quotes` бере в лапки кожну комірку, яка інакше прочиталася б як інше
   значення. Блок кодується, лише коли оцінка вказівника плюс TOON менша за оцінку JSON, тож
   таблиця, яка б збільшилася, лишається недоторканою і не залишає рішення в архіві.
6. **Спершу архів, потім заміна.** `cx.put_archive` зберігає оригінальний текст,
   `cx.put_archive_decision` фіксує заміну для пізніших ходів, а блок стає `[toon <8-char id>]`,
   за яким іде таблиця. `Measurement { plugin: "toon", kind: "encode" }` повертається і записується
   хостом.
7. **Відновлення.** `rtok expand <id>` повертає оригінальний JSON і записує рядок `toon`/`expand`;
   після цього id ніколи не перекодовується.

## Де це живе

| Блок | Код |
| --- | --- |
| ToonPlugin::proxy_filter, увімкнено? | `src/plugins/toon/mod.rs` (`ToonPlugin::proxy_filter`) |
| outside_live_zone | `src/plugins/archive/` (`outside_live_zone`, `block_text`) |
| archive_decision | `src/plugins/toon/mod.rs` (`rewrite_block`, `skips_foreign_pointer`, `PREFIX`) |
| tabular_keys | `src/plugins/toon/mod.rs` (`tabular_keys`) |
| encode | `src/plugins/toon/mod.rs` (`encode`, `encode_cell`, `needs_quotes`) |
| Блоби архіву і рішення | `crates/rtok-store/` (`archive_decisions`, `measurements`), `archive_dir` |
| expand | `src/expand.rs` (`fetch`) |
| Конфігурація | `crates/rtok-config/` (`[plugins.toon]` `enabled`, `min_rows`) |

## Інваріанти

- Без втрат: оригінальний текст архівується до заміни блока, а `expand <id>` його повертає.
  `decode` існує в тестовій збірці як оракул зворотного перетворення для `encode`.
- Таблиця, яка не зменшилася б, лишається як є, і для неї не записується рішення в архіві.
- Останні ходи (`keep_turns`) ніколи не чіпаються, а збережене рішення відтворюється як є, тож
  ранні ходи лишаються стабільними за байтами.
- `toon` ніколи не відтворює чужий вказівник (`archive`, `json_tree`), тож один блок дає один
  рядок вимірювання.
- Немає рядка `Measurement`, немає заяви про економію: кожне переписування повертає рядок
  `toon`/`encode`.
