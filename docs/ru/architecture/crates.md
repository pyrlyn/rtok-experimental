# Крейты

![Рабочая область Cargo: бинарники rtok и rtok-hook, библиотека rtok и крейты под crates/ с рёбрами зависимостей](../../architecture/crates.svg)

Исходник: [`crates.d2`](../../architecture/crates.d2). Индекс: [все диаграммы](README.md).

rtok поставляется одним пакетом с двумя бинарниками. Библиотека в `src/` содержит поверхности и плагины; всё, что имеет
собственный контракт или тяжёлую зависимость, которая должна оставаться в стороне от остального, живёт в крейте под `crates/`.

## Пошагово

1. **Два бинарника.** `rtok` (`src/main.rs`) — это все подкоманды. `rtok-hook` (`src/bin/rtok-hook.rs`) — клиент только на std,
   который хост может запускать на каждый вызов хука: он обращается к резидентному `rtok hook --serve` и при необходимости
   запускает `rtok hook` (см. [Поток хука](hook-flow.md)). Он линкуется только с крейтом протокола `rtok-hook`, поэтому
   стартует быстро.
2. **Библиотека** зависит от каждого крейта ниже и встраивает React-панель: `web/` собирается в `web/dist` и отдаётся
   `src/web/spa.rs`; в путь хука она не линкуется.
3. **Контракты.** `rtok-plugin-sdk` — контракт плагина (D25); он не зависит ни от одного крейта рабочей области.
   `rtok-agent-sdk` — контракт установки в хост: обратимые, идемпотентные правки с резервными копиями и `--dry-run`.
   `rtok-hook` — протокол между клиентом и резидентом.
4. **Владельцы тяжёлых зависимостей.** `rtok-store` — единственный крейт, который называет `diesel` (модели, встроенные
   миграции, `Store`). `rtok-config` владеет многоуровневой конфигурацией figment, правками `toml_edit` и эталонной
   конфигурацией. `rtok-mcp` содержит логику установки и статуса MCP для каждого хоста за трейтом `Fs`. `rtok-sys` содержит
   шимы ОС, которым нужен `unsafe` на Windows (процесс, flock); `rtok-log` — ротируемый текстовый журнал.
5. **WASM.** `rtok-wasm-demo-guest` — пример плагина на `no_std`, собранный под `wasm32-unknown-unknown`; фича `wasm-host`
   загружает такие гостевые модули во время выполнения (см. [wasm](plugins/wasm.md)).
6. **`workspace-hack`** генерируется `cargo hakari`, поэтому унификация фич одинакова для каждого участника. Так инкрементальные
   сборки не пересобирают общие зависимости.

## Где это находится

| Блок | Код |
| --- | --- |
| Рабочая область и бинарники | `Cargo.toml` (`[workspace]`, `[[bin]]`) |
| Крейты | `crates/<name>/` |
| Панель | `web/`, `src/web/spa.rs` |
| Проверки владения зависимостями | `tests/deps.rs` |
| Конфигурация Hakari | `.config/hakari.toml`, `workspace-hack/` |

## Инварианты

- `rtok-plugin-sdk` не зависит ни от одного крейта рабочей области; `rtok-hook` использует только std.
- Только `rtok-store` называет `diesel`; ничто в `src/` этого не делает.
- `cargo build --no-default-features --features measure` собирается: ни одному плагину не нужен другой.
