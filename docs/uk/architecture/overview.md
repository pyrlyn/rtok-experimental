# Огляд

![Огляд rtok: агенти для написання коду звертаються до трьох поверхонь, які мають спільний реєстр плагінів і один журнал у SQLite](../../architecture/overview.svg)

Джерело: [`overview.d2`](../../architecture/overview.d2). Індекс усіх діаграм: [README](README.md).

rtok — це один бінарник на Rust. Агент для написання коду звертається до нього через три поверхні; кожна поверхня будує той самий реєстр плагінів, передає кожному увімкненому плагіну `Ctx` і записує те, що зробили плагіни, в один файл SQLite. Поверхні оператора лише читають цей файл.

## Покроково

1. **Агент для коду звертається.** Claude Code запускає `rtok hook <event>` для кожної події хука (встановлюється командою `rtok agents install claude`). Хост також може запустити `rtok mcp` як сервер MCP, а хост, у якого можна налаштувати базову URL-адресу API, може надсилати свій трафік LLM через `rtok proxy`. Підключення кожного хоста розміщене в `src/agents/<host>/`.
2. **Поверхня будує реєстр.** `Registry::new(&config)` бере кожен плагін, скомпільований у бінарник (одна фіча Cargo на кожен id плагіна, `default = all`), і залишає ті, у яких `[plugins.<id>] enabled` істинне; якщо ключа немає, діє `Manifest::default_on`.
3. **Плагіни діють через один трейт.** Поверхня викликає метод трейту для своєї події: `pre_tool` (відхилити або переписати виклик інструмента), `post_tool` (лише додати контекст), `session_start` / `prompt_submit` (ін'єкції, які бюджетує `inject`), `mcp_tools` або `proxy_filter`. Кожен метод має порожню реалізацію за замовчуванням, тож плагін реалізує лише те, що оголошує у своєму маніфесті.
4. **Скорочення лишається без втрат.** Плагін, що скорочує вивід, записує оригінал у `archive_dir/<id>` і лишає в тому, що бачить модель, вказівник `expand <id>`.
5. **Економія — це рядок.** `Ctx::record` записує `Measurement` (токени до і після) у SQLite. Заява про економію без рядка не існує.
6. **Оператори читають журнал.** `rtok stats`, `rtok tui` і `rtok web` показують ту саму модель читання (D23) поверх сховища; жоден з них не стоїть на шляху хука.
7. **Проксі пересилає.** `rtok proxy` записує запит, дає плагінам `proxy_filter` скоротити результати інструментів у ньому, пересилає його провайдеру і зберігає справжнє `usage`, яке повернув провайдер.

## Де це живе

| Блок | Код |
| --- | --- |
| Поверхня хуків | `src/hooks/` (диспетчер); `crates/rtok-hook/` (клієнт лише зі std для необов'язкового резидентного `rtok hook --serve`, D32) |
| Поверхня MCP | `src/mcp.rs`, `src/mcp/` |
| Поверхня проксі | `src/proxy/` |
| Реєстр | `src/plugins/mod.rs` (`all()`, `Registry`) |
| `Ctx`, `Plugin`, `Measurement` | `crates/rtok-plugin-sdk/` (контракт), `src/plugin.rs` (рантайм хоста) |
| Конфігурація | `crates/rtok-config/`, реекспортується як `src/config/` |
| Сховище SQLite | `crates/rtok-store/` |
| Поверхні оператора | `src/cli/`, `src/tui/`, `src/web/`, `src/model/` |

## Інваріанти

- Хук завершується з кодом 0 у межах бюджету 10 мс і передає подію без змін у разі будь-якої помилки.
- PostToolUse може лише додавати контекст; скоротити те, що бачить модель, можуть лише переписування в PreToolUse, інструмент MCP або проксі (D2).
- Плагіни ніколи не залежать один від одного: `cargo build --no-default-features --features measure` збирається.
