# Обзор

![Обзор rtok: агенты для программирования обращаются к трём поверхностям, которые используют один реестр плагинов и один журнал учёта в SQLite](../../architecture/overview.svg)

Исходник: [`overview.d2`](../../architecture/overview.d2). Индекс всех диаграмм: [README](README.md).

rtok — это один бинарник на Rust. Агент для программирования обращается к нему через три поверхности; каждая поверхность
строит один и тот же реестр плагинов, передаёт каждому включённому плагину `Ctx` и записывает то, что сделали плагины,
в один файл SQLite. Операторские поверхности только читают этот файл.

## Пошагово

1. **Агент для программирования обращается к rtok.** Claude Code запускает `rtok hook <event>` для каждого события хука
   (устанавливается командой `rtok agents install claude`). Хост также может запустить `rtok mcp` как MCP-сервер, а хост с
   настраиваемым базовым URL API может направить свой трафик LLM через `rtok proxy`. Подключение каждого хоста находится в
   `src/agents/<host>/`.
2. **Поверхность строит реестр.** `Registry::new(&config)` берёт все плагины, скомпилированные в сборку (одна функция Cargo
   на каждый id плагина, `default = all`), и оставляет те, у которых `[plugins.<id>] enabled` равно true, с откатом к
   `Manifest::default_on`.
3. **Плагины действуют через один трейт.** Поверхность вызывает метод трейта для своего события:
   `pre_tool` (отклонить или переписать вызов инструмента), `post_tool` (только добавить контекст), `session_start` /
   `prompt_submit` (инъекции, ограниченные `inject`), `mcp_tools` или `proxy_filter`. У каждого метода есть пустая
   реализация по умолчанию, поэтому плагин реализует только то, что объявляет в своём манифесте.
4. **Сокращение остаётся без потерь.** Плагин, который сокращает вывод, записывает оригинал в `archive_dir/<id>` и оставляет
   в том, что видит модель, указатель `expand <id>`.
5. **Экономия — это строка.** `Ctx::record` записывает `Measurement` (токены до и после) в SQLite. Заявления об экономии
   без строки не существует.
6. **Операторы читают журнал.** `rtok stats`, `rtok tui` и `rtok web` выводят одну и ту же модель чтения (D23) поверх
   хранилища; ни одна из них не стоит на пути хука.
7. **Прокси пересылает.** `rtok proxy` записывает запрос, позволяет плагинам `proxy_filter` сократить в нём результаты
   инструментов, пересылает его провайдеру и сохраняет реальный `usage`, который вернул провайдер.

## Где это находится

| Блок | Код |
| --- | --- |
| Поверхность хуков | `src/hooks/` (диспетчер); `crates/rtok-hook/` (клиент только на std для необязательного резидентного `rtok hook --serve`, D32) |
| Поверхность MCP | `src/mcp.rs`, `src/mcp/` |
| Поверхность прокси | `src/proxy/` |
| Реестр | `src/plugins/mod.rs` (`all()`, `Registry`) |
| `Ctx`, `Plugin`, `Measurement` | `crates/rtok-plugin-sdk/` (контракт), `src/plugin.rs` (рантайм хоста) |
| Конфигурация | `crates/rtok-config/`, реэкспортируется как `src/config/` |
| Хранилище SQLite | `crates/rtok-store/` |
| Поверхности оператора | `src/cli/`, `src/tui/`, `src/web/`, `src/model/` |

## Инварианты

- Хук завершается с кодом 0 в пределах своего бюджета в 10 мс и на любой ошибке пропускает событие без изменений.
- PostToolUse может только добавить контекст; уменьшить то, что видит модель, могут только PreToolUse с переписыванием,
  инструмент MCP или прокси (D2).
- Плагины не зависят друг от друга: `cargo build --no-default-features --features measure` собирается.
