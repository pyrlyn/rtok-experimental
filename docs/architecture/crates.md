# Crates

![The Cargo workspace: the rtok and rtok-hook binaries, the rtok library, and the crates under crates/ with their dependency edges](crates.svg)

Source: [`crates.d2`](crates.d2). Index: [all diagrams](README.md).

rtok ships as one package with two binaries. The library under `src/` holds the surfaces and
the plugins; everything with a contract of its own, or a heavy dependency that must stay out
of the rest, lives in a crate under `crates/`.

## Walkthrough

1. **Two binaries.** `rtok` (`src/main.rs`) is every subcommand. `rtok-hook`
   (`src/bin/rtok-hook.rs`) is the std-only client a host may run per hook call: it asks the
   resident `rtok hook --serve` and falls back to starting `rtok hook` (see
   [Hook flow](hook-flow.md)). It links only the `rtok-hook` wire crate, so it starts fast.
2. **The library** depends on every crate below and embeds the React dashboard: `web/` is
   built to `web/dist` and served by `src/web/spa.rs`; it is not linked into the hook path.
3. **Contracts.** `rtok-plugin-sdk` is the plugin contract (D25) and depends on no workspace
   crate. `rtok-agent-sdk` is the host-install contract: reversible, idempotent edits with
   backups and `--dry-run`. `rtok-hook` is the wire between client and resident.
4. **Owners of heavy dependencies.** `rtok-store` is the only crate that names `diesel` (models,
   embedded migrations, `Store`). `rtok-config` owns figment layering, `toml_edit` edits and
   the reference config. `rtok-mcp` holds the per-host MCP install and status logic behind an
   `Fs` trait. `rtok-sys` holds the OS shims that need `unsafe` on Windows (process, flock);
   `rtok-log` is the rotating text log.
5. **WASM.** `rtok-wasm-demo-guest` is a `no_std` example plugin built to
   `wasm32-unknown-unknown`; the `wasm-host` feature loads such guests at run time (see
   [wasm](plugins/wasm.md)).
6. **`workspace-hack`** is generated by `cargo hakari` so feature unification is the same for
   every member, which keeps incremental builds from recompiling shared dependencies.

## Where it lives

| Box | Code |
| --- | --- |
| Workspace and binaries | `Cargo.toml` (`[workspace]`, `[[bin]]`) |
| Crates | `crates/<name>/` |
| Dashboard | `web/`, `src/web/spa.rs` |
| Dependency ownership checks | `tests/deps.rs` |
| Hakari config | `.config/hakari.toml`, `workspace-hack/` |

## Invariants

- `rtok-plugin-sdk` depends on no workspace crate; `rtok-hook` is std-only.
- Only `rtok-store` names `diesel`; nothing under `src/` does.
- `cargo build --no-default-features --features measure` builds: no plugin needs another.
