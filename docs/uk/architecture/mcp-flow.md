# Потік MCP

![rtok mcp: транспорти stdio, HTTP і обгортки подають дані в один Server, який перелічує вбудовані інструменти, інструменти координації та плагінів, перевіряє кожен tools/call і записує його](../../architecture/mcp-flow.svg)

Джерело: [`mcp-flow.d2`](../../architecture/mcp-flow.d2). Індекс: [усі діаграми](README.md).

`rtok mcp` — це поверхня, яка може *замінити* інструмент хоста, а не лише прикрасити його: агент, що викликає `read` або `search` у rtok, отримує скорочену відповідь напряму, чого хук PostToolUse ніколи не дасть (D2). Той самий `Server` відповідає через stdio і через HTTP, а третій режим обгортає чужий сервер MCP і скорочує його довгі результати без втрат.

## Покроково

1. **Старт.** `mcp::run` будує `Server` (один `Runtime` на процес), запускає завдання зберігання даних сховища та тикер OTLP і створює фонові потоки: спостерігач файлів `graph` (якщо не `plugins.graph.watch = "off"`), перевірку стану графа, прибиральник worktree (коли `worktree.enabled`) і оновлення відстежуваних проєктів графа.
2. **Перелік інструментів один раз.** `Server::new` збирає вбудовані (`expand`, `ping`, `whoami`), інструменти координації (`worktree_*`, `agent_send`/`agent_inbox`, `agents_list`, `agent_show`, `agent_status_set`, `task_*`) і `Plugin::mcp_tools()` кожного увімкненого плагіна, вбудованого в репозиторій. WASM-плагіни поза репозиторієм не перелічуються, бо `invoke` для них не має гілки.
3. **Читання рядка.** Цикл stdio читає один рядок JSON-RPC (масив-пакет отримує відповідь масивом), і `handle_line` маршрутизує за методом: `initialize` узгоджує версію протоколу й відзначає, чи клієнт пропонує `roots`; на сповіщення відповіді немає; `tools/list` повертає перелічені інструменти.
4. **Перевірка виклику.** `call_tool` спочатку нормалізує аліаси аргументів (`prepare_args`), потім відхиляє інструмент, якого немає в переліку, і виклик без поля, яке вимагає власна `input_schema` інструмента. Обидва випадки повертають `CallToolResult::error`, тож агент бачить причину.
5. **Виклик.** `invoke` спрямовує ім'я до власника: `read`/`search`/`tree` — до плагіна `read`, `mem_*` і `handoff` — до `memory`, `symbol`/`callers`/`impact`/`outline`/`explore`/`graph_diff`/`graph_export` — до `graph` (обмеженого через `graph::scope::resolve`), `docs_*` — до `docs`, `expand` — до архіву. Плагін, що скорочує свою відповідь, зберігає оригінал за id `expand`; сам `expand` обмежує великий оригінал через `cap_result`, який лишає маркер `expand(<id>)` для перегляду наступних частин.
6. **Запис.** Кожен виклик, успішний чи ні, проходить через `record`: один рядок `calls` (`kind = mcp_call`, плагін і назва інструмента), його `call_io` і три рядки `tokens` (аргументи як `before`, результат як `after` і як рядок `mcp` плагіна).
7. **HTTP.** `rtok mcp --http` обслуговує той самий `Server` через MCP Streamable HTTP; rmcp відповідає за транспорт, включно з перевірками Host і Origin, і передає лише `tools/list` та `tools/call` тому самому шлюзу перевірки, диспетчеру та `record`.
8. **Обгортка.** `rtok mcp -- <server argv>` запускає чужий сервер MCP через stdio і пересилає кожен кадр без змін, крім відповіді `tools/call`, текстові блоки якої перевищують правило cmd `[mcp]`: кожен такий блок архівується сирим, обрізається через `rules::apply` і закривається тим самим трейлером `expand`, який друкує `rtok run`. Якщо сховище не відкривається, обгортка є звичайною трубою (pipe).

## Де це живе

| Блок | Код |
| --- | --- |
| stdio-сервер | `src/mcp.rs` (`run`, `Server`, `handle_line`, `call_tool`, `invoke`, `record`) |
| HTTP | `src/mcp/http.rs` |
| Обгортка | `src/mcp/wrap.rs` |
| Інструменти координації | `src/mcp/worktrees.rs`, `src/mcp/messages.rs`, `src/mcp/agents.rs`, `src/mcp/tasks.rs` |
| Інструменти плагінів | `src/plugins/read/`, `src/plugins/memory/`, `src/plugins/graph/`, `src/plugins/docs/` |
| Журнал | `crates/rtok-store/` (`insert_call`, `insert_call_io`, `insert_tokens`) |

## Інваріанти

- Інструмент, якого немає в переліку, не можна викликати ні через stdio, ні через HTTP.
- Результат, який rtok скорочує, завжди має id `expand`; оригінал лежить в архіві.
- Обгортка ніколи не змінює кадр, який не скорочує, і ніколи не валить чужий сервер.
