# Поток хука

![Один вызов хука: хост запускает rtok hook, входные данные проверяются, адаптируются и по событию передаются включённым плагинам, а объединённый вывод возвращается в stdout](../../architecture/hook-flow.svg)

Исходник: [`hook-flow.d2`](../../architecture/hook-flow.d2). Индекс: [все диаграммы](README.md).

Хост запускает `rtok hook <event>` один раз на каждое событие хука, передавая JSON события через stdin. rtok
читает его, даёт каждому включённому плагину отреагировать, сливает то, что они вернули, в один объект JSON в формате
хоста, выводит его в stdout и завершается с кодом 0. Каждый путь ошибки печатает `{}`, так что хост продолжает работу,
как будто rtok не установлен (fail open, D1).

## Пошагово

1. **Вход.** Хост либо запускает `rtok hook <event> --host <h>` напрямую (`src/cli/hook.rs` → `hooks::run`), либо запускает
   клиент `rtok-hook` только на std, который передаёт вызов резидентному `rtok hook --serve` через Unix-сокет или именованный
   канал (`src/hooks/resident.rs`, D32). Если резидент отказал или отсутствует, клиент сам запускает `rtok hook`, так что
   резидент никогда не обязателен. Оба пути заканчиваются в `hooks::run`.
2. **Охрана.** `hooks::run` читает не больше `core.hook_max_input_bytes` и оборачивает диспетчеризацию в `catch_unwind`.
   Слишком большой stdin, ошибка чтения или паника записываются в лог, и печатается `{}`. При `hook.fail_open = false`
   (только для отладки) те же случаи вместо этого вызывают панику.
3. **Адаптация.** `dispatch_owned_strict` разбирает `HookInput` и переписывает полезную нагрузку чужого хоста в имена полей
   Claude (`adapt_grok`, `adapt_cursor`, `adapt_gemini`, …), определяет id сессии (сначала stdin, затем
   `$<core.session_env>`) и открывает `Runtime` (конфигурация и хранилище). Хранилище, которое остаётся заблокированным дольше
   времени ожидания, пропускает вызов и откладывает `SessionEnd`.
4. **Запись вызова.** `hooks::dispatch` строит `Registry`, регистрирует или обновляет строку агента этой сессии
   (`register_agent`) и пишет одну строку `calls` для события.
5. **Маршрутизация по событию.**
   - `PreToolUse` → `pre_tool`: каждый плагин может вернуть `Deny` или `Rewrite`. Первый `Deny` возвращается сразу;
     иначе побеждает последний `Rewrite` (`updatedInput`).
   - `PostToolUse` → `post_tool`: плагины могут только добавить контекст. Строки склеиваются, ожидающие сообщения агентов
     идут первыми, а `cap_budget` обрезает результат до `plugins.inject.budget_tokens`, оставляя указатель `rtok expand`
     на то, что было отброшено.
   - `SessionStart`, `UserPromptSubmit`, `SubagentStart`, `PostCompact` → `inject_event`: каждый `Injection` (плюс id агента
     и заметки о заявленных рабочих деревьях) передаётся в `inject::apply`, который упорядочивает их по приоритету и
     выводит до исчерпания бюджета.
   - `PreCompact` → `pre_compact` каждого плагина, затем `memory::compact_context` как контекст.
   - `SessionEnd` → `checkpoint::save_session`, `end_agent` (который также снимает блокировку рабочего дерева агента) и
     `end_session`.
6. **Изоляция каждого плагина.** Каждый вызов трейта выполняется в собственном `catch_unwind`; паникующий плагин
   записывается в лог (`log_panic`) и отбрасывается, остальные продолжают учитываться.
7. **Ответ.** Объединённый `HookOutput` сериализуется; `copilot_output`, `cursor_output`, `gemini_output`, `codex_output`
   и подобные функции перестраивают его для хостов с другой оболочкой. Длительность вызова и его stdin/stdout попадают в
   `calls` / `call_io`; `Stop` и `SessionEnd` также запускают дочерний процесс экспорта OTLP.

## Где это находится

| Блок | Код |
| --- | --- |
| `rtok hook <event>` | `src/cli/hook.rs`, `src/hooks/mod.rs` (`run`) |
| Резидент и клиент | `src/hooks/resident.rs`, `crates/rtok-hook/` |
| Адаптация | `src/hooks/mod.rs` (`dispatch_owned_strict`), `src/hooks/types.rs` (`HookInput::adapt_*`) |
| Диспетчеризация | `src/hooks/mod.rs` (`dispatch`, `pre_tool`, `post_tool`, `inject_event`, `cap_budget`) |
| Сообщения агентов, попадающие в контекст | `src/hooks/push.rs` |
| Бюджет инъекций | `src/plugins/inject/` (`apply`) |
| Журнал учёта | `crates/rtok-store/` (`record_call`, `insert_hook_call_io`, `register_agent`) |

## Инварианты

- Выход с кодом 0 в пределах бюджета 10 мс на каждом пути; хук никогда не блокирует агента.
- PostToolUse только добавляет контекст; результат инструмента нельзя заменить из хука в Claude Code.
- Паника одного плагина не убирает вывод другого плагина.
- Повторная доставка одного вызова инструмента (хук плагина плюс оставшийся хук в настройках) записывается один раз:
  `Runtime::once` ключует измерения по `<event>:<tool_use_id>`.
